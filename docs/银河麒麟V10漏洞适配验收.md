日期：2026-11-03。需求：用户主机主要为银河麒麟高级服务器V10，补齐官方漏洞来源、Agent系统识别和软件清单扫描。

## 已实现范围

复用现有漏洞数据源、快照、原始制品、扫描计划和风险流程，新增KYLIN官方提供方，无数据库结构变更。来源固定为[麒麟官方UpdateInfo目录](https://update.cs2c.com.cn/NS/UpdateInfo/)，禁止自行配置任意地址。按SP和处理器架构分别建立来源，不套用RHEL/openEuler的补丁版本。

本地已创建并启用8组来源，共7508条分支/架构范围内的安全公告记录；不同范围可能涉及同一公告或CVE，不是7508个独立漏洞，也不是资产风险数量。同步周期每天，72小时未成功同步标过期。普通bugfix更新不参与安全匹配。

官方repomd定义的压缩文件路径、大小、SHA-256及解压大小、SHA-256逐一核验。XML解析限制大小、深度、节点数量和属性长度，拒绝DTD、实体声明及处理指令。完整XML字节以gzip保留，支持下载`.xml.gz`；快照保存repomd原文及摘要。原文中超长参考标题仅在展示摘要中截短并标记，原始XML不截断。未带时区的厂商日期仅保留原值，不假定UTC。失败或校验不一致时保留上次有效快照。

Agent读取`/etc/os-release`及`/etc/.kyinfo`中`[dist]`的产品、milestone识别结果；不读取或上报servicekey授权内容，不执行shell。新版增加可选识别字段，原有非麒麟系统结构保持不变。未知SP、桌面版、中标麒麟、其他专用版及不支持的架构不推定等价。

匹配依据为相同产品/SP/主机架构下的同名二进制包、明确包架构和完整RPM epoch:version-release；noarch按无架构包核对。缺字段、包架构异常、旧Agent无法识别SP时显示无法完整判断。KYSA为公告身份，涉及的多个独立CVE保存为上游引用；分别展示其评分、KEV和来源，不把一个CVE的利用状态套给另一个CVE。

## 使用方法

1. 升级并部署本次包含SP采集能力的Agent，核对资产的实际产品、SP、架构和RPM完整软件清单。手工修改资产显示名称不能替代采集。
2. 在“策略中心 → 来源管理 → 漏洞数据源”的“多源情报与快照”查看8组来源，进入名称查看快照与原始文件。其他环境可运行`node --env-file=.env scripts/initialize-kylin-libraries.cjs`幂等初始化。
3. 在软件清单扫描计划中选择目标主机、对应麒麟来源；混合环境可同时选多个SP/架构来源，系统分别隔离匹配。若需要CVE评分和在野利用上下文，再选已成功同步的NVD/CISA来源。
4. 运行计划后查看风险及版本证据；修复后重新采集并复测，已有风险不会因来源更新自动关闭。
