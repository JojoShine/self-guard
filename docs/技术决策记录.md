# 实施技术决策记录

日期：2026-10-30。用户授权在其休息期间自主推进，剩余常规技术选择由实施方决定，不设置额外人工审批门槛。以下记录不改变原需求范围。

## 当前选择

- 管理后端采用 NestJS 模块化单体，业务数据库 PostgreSQL17，Prisma6.19.3。前端 React/Vite/Zustand/Ant Design。Agent 与 WAF 使用 Go 标准库。
- 任务调度先依靠 PostgreSQL 行锁、状态比较更新及持久执行记录，不引入额外消息队列。扩大吞吐时需验证调度容量与故障模型。
- 管理会话是随机令牌的数据库哈希，组件使用独立令牌。注册支持客户端先持久化随机凭据后重试，防止响应丢失导致身份不可恢复。
- 规则调度60秒检查一次到期项，执行间隔可配置。全量漏洞规则检测按稳定资产ID分批遍历，不截断前1000台；响应只携带前100条结果，完整结果在检测记录查询。
- 漏洞检测支持精确版本及 Debian/Ubuntu 版本范围；受限 OSV 源定时刷新、记录失败重试与覆盖缺口。软件清单采集不完整时不以未匹配推断安全。
- CONFIG_VALUE仅支持明确KEY=VALUE、精确旧值前置检查和64KiB上限。不执行任意脚本，不重启服务。原位修改不是崩溃原子更新，恢复标记存在时停止Agent等待人工核对。
- Linux修复使用逐级目录描述符及no-follow打开文件，拒绝多硬链接目标。状态与恢复标记采用私有权限、同步文件及父目录。
- WAF管理面与流量面分离，策略保留最后有效磁盘快照；事件使用有界持久outbox，仅2xx后移除。队列满、磁盘故障和永久拒绝有明确限制，不宣称无限可靠。
- 附件存PostgreSQL，每文件1MiB、每对象最多50个/20MiB；默认下载为二进制，不在页面执行上传内容。

## 环境限制与处理

Docker虚拟磁盘可用空间为0，标准镜像构建失败。未清理其他项目镜像、容器或数据。当前开发栈复用已有镜像，数据库、缓存、运行库及测试夹具挂载在本项目`.artifacts`下。Node镜像所需公开OpenSSL运行库来自相同发行版的官方PostgreSQL镜像。

这解决了本次开发联调，但不是标准生产镜像构建的替代验收。标准镜像重建仍待Docker空间问题解决后验证。

## 本轮完成的详细决策

- 主机基线/日志/FIM 本地周期执行，漏洞规则服务端手动/定时执行，跨事件窗口关联在服务端持久化。基线样本调用实际 Agent 的只读引擎，避免浏览器或另一份实现得出不同结果。
- PostgreSQL 保存有界结构化遥测及脱敏访问流；正文需 Agent 和中心双端显式开启。中心日志类行数限额在同一入库事务检查；拒收后组件保留未确认队列。高吞吐存储不预设无限容量。
- 任务固定模板版本写入业务记录，目标与参数创建后不可变；窗口修改重审批。模板停用同时约束创建与领取，领取按键集扫描避免被已停用或等待批次的旧任务阻塞。
- 自动独立读回与原始安全复测分开：只有实际检测依据匹配时才自动关闭风险。无关漏洞及无法绑定原始秘密预期的配置风险保留待安全复测；回滚复验重新开放风险。
- 采集/执行可按独立进程部署，服务端签名任务、root 结果签名和本地允许范围共同约束。远程升级需要单独发布公钥与允许来源；不配置即关闭。
- WAF 本地访问快照用于快速查看，完整 handler 访问流另走持久队列。平台证书私钥加密保存，节点使用受信管理连接热同步并保留私有离线缓存。
- 工作台所有数量可按原统计规则下钻；报表采用 UTC 创建范围和当前状态，不冒充完成日期统计。保存视图按用户隔离，导出和列表共享筛选/权限。
- 连续运行采用一次性 init + 双 API + readiness gateway，避免多实例并发生成 Prisma 客户端；数据库维持单节点，独立验证备份与恢复。

本轮审查发现的通知范围丢失、无关修复误关风险、模板饥饿、手动回滚复验状态覆盖、空签名密钥和重复部署密钥问题均进入回归检查。最终执行结果见验收矩阵，历史失败日志仅作为调试证据。
