# 运行与验收说明

当前目录为用户指定工作目录；原目录无 Git 仓库，未创建远端或发布服务。测试只修改项目夹具、测试资产及独立数据库/schema，不清理其他项目 Docker 资源。

## 启动与运行拓扑

本机当前开发入口为 `http://127.0.0.1:5180`；数据库/API/Web/备份/WAF 使用 `compose.dev.yaml`。WAF 流量端口为 `127.0.0.1:5183`，管理测试端口只在容器网络内开放。

```sh
./scripts/init-env.sh
node scripts/provision-keys.cjs
./scripts/prepare-dev-runtime.sh
docker compose -f compose.dev.yaml up -d
```

现有环境 Docker VM 磁盘满，使用已存在的官方 Node/PostgreSQL/Go 镜像和本项目宿主目录挂载；不依赖重新构建镜像层。应用二进制放在 `.artifacts/bin`，用临时文件构建后原子替换，避免覆盖正在运行的文件。全套检查会构建这两个二进制。

标准镜像部署使用根目录 `docker compose up -d --build`，API 的构建上下文是仓库根目录，以便同时构建只读规则测试程序。`.dockerignore` 排除私有配置、运行数据和依赖缓存。该标准镜像流程本轮没有因磁盘限制重复尝试，不能据此声称镜像已重建通过。

另有 `compose.runtime.yaml`：一次性 init 迁移/生成/编译，两个 API 节点共享数据库和会话，gateway 提供静态生产构建与就绪探测/故障绕行；独立数据库目录不覆盖开发库。生产构建先运行前端 build。

```sh
docker compose -f compose.runtime.yaml up -d
# TLS 参考拓扑，需先准备下面说明的受控证书文件：
docker compose -f compose.runtime.yaml -f compose.tls.yaml up -d
```

TLS 示例读取 `.artifacts/tls-fixture/api.crt`、`api.key`；测试证书 SAN 包含 api、api-replica、localhost、127.0.0.1，gateway 信任该测试 CA。真实部署替换为自己的证书与路径，限制私钥权限。该夹具不会代替公共域名签发，也不关闭 TLS 验证。HTTP/TLS 拓扑共用 5182，选择一个运行；测试后可停止两个 API 和 gateway 释放资源，数据库保留。

## 组件部署与凭据

- Agent 部署、CPU/内存限制、非特权采集与 root 执行器、任务/结果签名、远程升级及恢复命令见 `services/agent/README.md` 和同目录 systemd 样例。
- WAF 独立部署、可信代理/规范化/限制、证书与持久目录见 `services/waf/README.md`。API 管理测试地址通过 `WAF_TEST_URL` 配置；生产使用受信 HTTPS，开发容器网络只在 `WAF_DEVELOPMENT=true` 时允许 HTTP。
- `DATA_ENCRYPTION_KEY` 为 32 字节十六进制密钥；`TASK_SIGNING_PRIVATE_KEY` 为 Ed25519 PKCS8 DER 的 Base64，均由 provisioning 生成并私有保存。只向执行器分发 `.artifacts/executor-public-key.txt` 中的服务端公钥，执行器结果公钥由主机单独导出并绑定资产。
- `AGENT_UPGRADE_PUBLIC_KEY` 与 `AGENT_UPGRADE_ORIGINS` 默认留空，远程升级显式关闭。部署时从受控发布流程提供发布公钥与允许 HTTPS origin；不从管理 API 上传发布私钥。

./scripts/check.sh

浏览器测试会创建明确标记的测试资产/规则/问题，结束后将其归档或停用，保留审计。并行修改前端可能触发刷新，因此在代码稳定后执行。截图、下载文件和检查日志保存于 `.artifacts/results`，不包括私有 `.env` 或私钥。

## 备份与加密密钥轮换

```sh
./scripts/backup.sh
./scripts/verify-backup.sh .artifacts/backups/<实际备份文件>.dump
```

验证恢复到独立临时数据库，成功后只删除该临时库。定期备份由 backup 工作进程读取界面策略并维护自身文件；先验证当前备份能恢复，再做真实恢复。真实恢复前停止业务写入，单独恢复并验证迁移、用户会话、风险/任务和组件身份，再切换服务；避免向运行库盲目覆盖。

需要轮换加密主密钥时，保留原密钥的受控备份，设置 `DATA_ENCRYPTION_PREVIOUS_KEY=原密钥`、`DATA_ENCRYPTION_KEY=新密钥`，重建 API 配置。在过渡期间可读新旧密文，新写入只用新密钥。

```sh
# 默认 dry-run，解密核对所有目标但不写入：
docker compose -f compose.dev.yaml exec -T api npx tsx prisma/rotate-secrets.ts
# 确认已有可恢复备份后，事务重加密 webhook 与证书私钥：
docker compose -f compose.dev.yaml exec -T api npx tsx prisma/rotate-secrets.ts --apply
```

任何目标解密失败则整个写事务回滚。完成并验证通知配置与 WAF 证书读取后移除旧密钥环境并重建 API；不要删除仍需恢复历史备份的旧密钥。工具只输出计数，密钥不进审计。任务签名公钥和发布公钥轮换应先在组件部署新信任，再切换服务端/发布方，避免未完成任务失去验证条件。

## 实测口径与限制

本轮使用 Linux arm64 官方容器。数据面参考测试每组件 CPU 0.5、内存 128 MiB，10 并发、1000 次合法代理请求；结果文件 `dataplane-profile.json` 记录延迟、吞吐、OOM 状态与采样内存。CPU/内存采样不是持续峰值或所有采集组合的容量保证。

控制面参考测试使用 1000 个测试资产、10000 个风险、10 并发，结果在 `capacity-profile.json`。独立双 API 演练验证既有会话在一个 API 停止后仍可使用，HTTP 和 TLS 均有记录。定期备份演练验证连续执行与数量保留；独立恢复验证实际数据可读取。

这些是已验证的初始部署参考。没有宣称所有 Linux 发行版、真实生产 systemd 服务、数据库自动切换、跨机房灾备、任意流量和公网证书都已完成现场验收；实际部署依据资源、业务样本和证书环境另做检查，不改变已确认功能范围。
