# 初版界面优化

2026-10-31。范围：现有 React/Ant Design 页面，保持后端能力和权限不变。用户要求优先优化 UI，沿用先前自主实施授权，不重复设置审批门槛。

## 本轮实际检查

当前浏览器截图保存于 `.artifacts/ui-audit/before`。
1. 工作台（01-overview）：同等大小指标卡占据首屏；待办和需处理风险在下方；窄窗口导航缩成单个文字，识别困难。
2. 全部发现（02-findings）：保存视图、密度、排序、日期、搜索等同时摊开，筛选占约300px；“状态代码”和资产UUID需要使用者理解内部字段。
3. 发现详情（03-finding-detail）：概要被ID和日期挤占，证据字符串二次序列化，显示转义JSON；动作、调查、关联、历史缺少清晰分组。

## 实施方向

- 采用克制的浅色控制台：白色工作区、统一蓝色操作、语义化风险色、清晰字重、表格数字对齐；沿用 Ant Design 和现有技术栈，不采用装饰性背景图或伪造图表。
- 导航使用同一图标体系，折叠后保留可识别图标和完整名称；统一面包屑、账户区和页面说明。
- 工作台使用紧凑核心指标、待办标签页和资产状态侧栏；业务分布、修复结果、WAF和最新发现按主次组织。全部指标继续下钻真实授权明细，不生成虚假分数或趋势。
- 列表默认展示搜索、严重程度、中文处置状态；日期/业务/负责人/资产/排序收进“高级筛选”；视图/密度/列配置属于表格工具层。保留原URL、已存视图、导出和逐项批量结果。
- 详情使用状态概要和结构化证据，原始JSON作为可选技术信息折叠。危险变更仍保留原审批/回滚限制。

## 验证

1. 前端类型检查、生产构建、必要的格式化/证据呈现测试。
2. 在1440与窄窗口检查真实页面：首屏可见工作重点，筛选折叠可展开，导航可识别，无页面横向溢出。
3. 真实UI复核搜索/筛选/明细/权限提示及详情交互，保存本轮改前与改后截图；不以旧截图或只通过接口测试替代视觉验证。
