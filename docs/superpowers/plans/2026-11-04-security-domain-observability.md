# 网络安全与数据安全分域：实施总计划与 P0 验证计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 当前会话默认原生执行；未经用户要求不分派实施子任务。

**Goal:** 在现有平台上建立严格分域，并验证按有效访问留存请求/完整返回数据的可行性、容量和覆盖边界。

**Architecture:** 复用 Go Agent 的采集、审计与交付机制，复用 NestJS/Prisma 控制面和 React/Ant Design 界面。持续观测后形成访问事件与正文引用，原包短时缓冲、必要固化；保持旁路，按组件验证 TLS 明文探针。先完成 P0，再分别制定共享基础、网络检测、数据采集/分类、证据存储的具体开发计划，避免在实际能力未明确时冻结协议实现和存储选型。

**Tech Stack:** 现有 Go 1.25、Node.js、TypeScript、NestJS、Prisma/PostgreSQL、React/Ant Design；P0 测试不新增线上依赖。

**Spec:** [已确认的 V0.2 业务规划](../../网络安全与数据安全业务重构规划评审稿.md)。执行者必须同时阅读本计划与业务规划，P0 测试结果不是后续阶段已经完成的证据。

## Global Constraints

- “普通访问不以触发告警为留存前提。”失败认证、权限拒绝、执行错误与异常请求保留；解析不了不等于无效流量。
- “有效访问的业务正文、返回数据及已固化的报文证据先按滚动 7 天设计；短时处理缓冲另设有界策略。”
- “不以 30 秒、60 秒后停止。”去除传输重传/重复观察点不能误删两次相同真实操作。
- 先前的完整返回数据要求继续有效，不能只按日志行估算容量，不能用摘要默默替代正文。
- 麒麟 V10、已有 CentOS、x86_64/ARM64 需要真实能力矩阵；不默认有 BTF，不默认均可使用同一种进程探针。
- 维持旁路，不关闭 TLS、不接管业务网络转发；探针和原生审计生产变更按已确认流程执行。
- 保留现有未提交变更；不创建提交、不推送、不在验证过程中升级生产 Agent 或改生产数据库。
- 保留旧摘要/六引擎元数据模式、旧链接及权限；不扩展通用主机执行器来修改数据库。
- CRS 原 100 RPS、30 分钟、零错误、附加 P95≤20 ms 门槛不变。

## Review Focus

1. 相同 SQL 被真实执行两次：两条访问都保留；同一次操作的 TCP 重传不多计。由任务 3 的对照流量验证。
2. TLS 或未知协议无法解析：显示缺口并按策略固化证据，不能算作可安全过滤的流量。由任务 3、4 验证。
3. 连接池/共享账号没有业务身份：最终操作用户保持未知。由任务 3 的会话清单断言验证。
4. 大结果与超大/无效容量输入：流式处理、有界内存；测算不接受溢出或漏算返回数据。由任务 1、3 验证。
5. 原包正常释放与业务证据丢失：分别计数；不宣称能够回溯已过短时窗口的原包。由任务 3 的缓冲边界实验验证。

## 3. P0 任务

### Task 1：建立离线有效访问容量计算

**Files:** Create `scripts/observability-capacity.cjs`、`scripts/observability-capacity.test.cjs`。

**Interfaces:**

- `calculateCapacity(input)`：输入 `dailyAccessCount`、`recordBytesPerAccess`、`requestBytesPerAccess`、`responseBytesPerAccess`、`retentionDays`、`dailyPinnedPacketBytes`、`evidenceCopies`、`dailyIndexBytes`、`indexRetentionDays`、`indexCopies`、`bufferBytes`。所有字段为显式提供的非负安全整数；天数与副本数至少为 1，天数不设静默默认。
- 输出 `dailyBusinessBytes`、`retainedBusinessBytes`、`retainedPinnedPacketBytes`、`evidenceBytesWithCopies`、`indexBytesWithCopies`、`bufferBytes`、`totalBytes`，均为安全整数；任何乘法/求和超出安全整数立即拒绝，不输出近似“成功”结果。
- CLI：`node scripts/observability-capacity.cjs <input.json>`；验证失败返回非零状态，不回显整个输入文件。此接口仅为离线工具，不是平台公共契约。

- [x] 写失败测试：100 万次/日、记录 1 KB、请求 0、返回 20 KB、7 天，断言每天业务正文为 21 GB、7 天为 147 GB；返回为 0 的对照仅得每天 1 GB、7 天 7 GB，工具不得自行假设有返回内容。
- [x] 写失败测试：固化原包、两份正文副本、不同索引保留天数和缓冲均只按各自口径计算；负数、小数、NaN、Infinity、缺失/未知字段和安全整数溢出均拒绝。
- [x] 执行 `node --test scripts/observability-capacity.test.cjs`，确认测试先因尚无实现失败。
- [x] 实现纯计算及严格 CLI 输入校验，不引入依赖、不假设压缩比例、不按链路 Mbps 替代访问大小。
- [x] 再运行上述测试，预期全部通过；手工使用规格第 10.2 节三组示例核对单份 7 天业务容量分别为 7 GB、147 GB、7.007 TB。
- [x] 在验证记录中保存实测输入的来源和采样时间；示例数据标明“假设”，不得作为现网测量结果。

### Task 3：验证有效访问提取与存储口径

**Files:** 实验产物放入 `.artifacts/results/security-observability/<run-id>/`；结论更新 `docs/安全观测P0验证记录.md`。使用既有隔离数据库测试方式与已验证采集工具，不修改生产 Agent。若需持久化测试辅助程序，执行时依据已选协议组件决定最小文件范围，先列明位置及许可证。

**Interfaces:** 每个实验输出访问对照清单，包含来源操作序号、会话标识、请求/响应引用和校验、认证/权限/执行/事务结果、完整性、业务用户是否可证实、原包正常释放数和意外丢失数。仅用合成业务数据，不在报告中记录秘密。

- [ ] 为 MySQL、Redis 和 PostgreSQL 建立实际可用的隔离实例清单；为每个实例先写客户端操作与预期响应对照，认证失败/权限拒绝/错误、重复相同真实操作及大结果必须包含。无可用实例列为未验证。
- [ ] 对选定且许可允许的现有解码组件/工具，先验证最小请求响应链路；按操作序号比较数量和响应字节/内容摘要，不以“抓到了流量”判定协议成功。
- [ ] 验证 TCP 重传/多观察点不增加业务次数，同一连接连续执行两次同语句仍是两次；未知协议/不完整帧必须形成缺口，不能算作节省。
- [ ] 分别验证 Redis 流水线/RESP3 推送与 MySQL 预编译/大结果；未覆盖功能列为部分支持，不能从普通查询推断支持完整协议。
- [ ] 使用共享账号场景证明只能确定数据库账号/进程；缺少可信应用上下文时不填写最终用户。
- [ ] 验证短时原包缓冲的正常到期、在窗口内固化和窗口外无法回取；有效访问正文继续存在。原包正常释放不得增加业务证据丢失计数。
- [ ] 测量过滤前观测字节、有效访问次数、记录/请求/响应字节、固化原包字节、解析失败与大结果分布；用任务 1 工具计算容量，并单独报告捕获/解析 CPU、内存与上传需求。
- [ ] 验证工具错误、解码器崩溃或配额不足时显式失败并保存缺口；实验结束仅清理本次命名隔离资源，禁止停止已有业务容器或修改整机网络。
