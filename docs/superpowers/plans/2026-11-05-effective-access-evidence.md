# 有效访问与请求响应证据实施计划

> **For agentic workers:** Use superpowers:executing-plans，当前会话原生连续执行，最后独立复核。保留既有工作区，不提交或推送，不修改生产环境。

**Goal:** 将已确认规划中的有效访问、完整请求/响应、分类预警与证据钻取落到实际运行链路，不用连接摘要代替访问证据。

**Architecture:** 沿用 Go Agent 身份、NestJS/Prisma 控制面及现有 React 组件。独立探针工作进程对显式批准的观察点采集，将请求/响应分段加密排队并持久化确认；平台独立证据目录保存加密正文，PostgreSQL 只保存访问索引、校验和、权限与覆盖状态。采集和上传不进入基础心跳队列。

**Tech Stack:** 现有 Go、TypeScript、PostgreSQL、React/Ant Design；复用标准库加密与 HTTP 解析。

**Spec:** [已确认 V0.2 规划](../../网络安全与数据安全业务重构规划评审稿.md)，尤其第6—11节；本计划继续已授权工作，无需重复方案审批。

## Global Constraints

- 保持旁路。TLS 不自动解密；只允许已评审的实际观察点，不改变业务转发或关闭加密。
- 普通成功、认证失败、权限拒绝、执行错误均留存。重复上传幂等，两次相同真实访问仍是两条。
- 请求/响应完整字节以有界分段保存；截断、丢包、不支持和未采集必须显式标记，不能默默替换为摘要。
- 正文捕获日起7天到期，上传不续期；索引不嵌正文或认证秘密。默认不自动启用生产探针。
- 正文读取、导出、部署分别授权，并与主机/实例范围取交集；读取有审计。
- 旧 Agent/数据库审计/流量摘要保持兼容；Oracle12c+和金仓缺介质继续如实列待验证。

## Review Focus

1. 跨主机/实例篡改目标与正文引用：收集凭据和人类读取均需范围校验。
2. 分段乱序、重传、崩溃重启、响应超配额：校验与确认绑定，缺口可查。
3. 捕获时间伪造、晚到及下载时刚过期：不延长7天、不读已到期正文。
4. 身份、路径、参数与返回值：未验证用户/链路不推断，秘密不进入索引和通知。
5. 原有普通访问与跨域导航：不以告警为前提，列表和导出维持真实领域。

## Task 1：证据契约与加密分段持久化

Files: `apps/api/src/access-contract.ts`、`access-evidence.ts`、相应测试、Prisma新模型与向前迁移。

接口：版本化观察记录绑定授权源；分段键含事件/方向/序号，提供 SHA256、捕获时间、原始长度、完整性。每段最多256KiB；请求/响应可有多段。AES-GCM加密，密钥按源派生，写入原子化，重复只接受完全相同内容。查询返回元信息，不嵌正文。

## Task 2：授权源、访问入库、分类与预警

接口：管理员配置显式授权的主机/实例观察源；探针使用独立范围凭据，撤销立即生效；访问序号稳定，分段传完后校验并确认。普通访问独立保存。记录认证/权限/执行/完整性，关联分类版本和规则结果；最终用户仅有可信来源时存在。正文按需读取/导出且独立授权，审计不包含正文。
