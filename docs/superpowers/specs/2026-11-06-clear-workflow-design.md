# 核心安全使用流程重整

用户确认“清晰简单”。沿用已讨论的结构：接入并确认覆盖 → 查看问题 → 核查证据。保留网络安全、数据安全边界及业务分组，不增加安全能力、不改采集授权或生产环境。

- 概览先呈现待确认问题（明确仅OPEN状态），给出接入后的使用步骤；资产与访问总量仅为背景，不能冒充待处理问题或采集覆盖。
- 网络安全使用“流量分析、漏洞扫描、安全告警”。流量分析统一入口，分连接记录和协议记录。原network-hosts、network-sensors路由保留，分别承载两个视图；来源和记录标识不合并、不累计重复流量。
- 连接视图选择主机后展示持续采集结果；服务端口、临时捕获结果为次级标签，采集设置沿用已有抽屉。登记、最近Agent上报、流量上报分别解释。
- 协议视图默认只看连接流，可选择HTTP/DNS/TLS/协议异常；规则告警进入已有安全告警，精确源事件链接继续有效。来源维护和引擎统计进入采集配置，不占据日常首屏；不得把回放当作在线。
- 数据安全日常页保留请求响应和数据库审计；采集配置单独进入，现有探针、规则、凭据与权限不变。
- 告警页去掉已由当前页面确定的领域/类型列，不将导入作为主要操作。证据和技术字段按需展开，保留读取权限。
- 不删除历史数据、不迁移协议、不添加依赖、不提交或部署生产。现有脏工作区按用户要求保留；在当前功能分支直接修改。

方案选择：采用已确认的使用流程整合；仅改名无法修复配置和结果混排，完全重建前后端不符合当前范围。
