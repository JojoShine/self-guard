# CRS运行发布与Nginx自动接入

用户要求补齐CRS正式发布，并确认现有和新业务均采用宿主机Nginx反向代理。沿用原WAF持久链路验收门槛，不以开启环境开关代替验收；不修改用户实际业务入口。本轮在本地/专用夹具实现与验证。

选择复用现有Nginx事务引擎、已保存SSH连接、Agent和WAF签名发布流程。独立公网WAF会改变现有证书/入口，当前没有必要；复杂Nginx整份重写不能可靠保留业务语义，继续明确拒绝。

现有业务：明确选择站点、主机与配置文件；平台经授权SSH执行只读预检，返回原配置摘要、保留项和修改项。用户确认这份具体预检后执行。目标配置/管理连接/资产/站点变化则拒绝。自动备份、部署固定摘要WAF、修改唯一proxy_pass、nginx -t和平滑加载、比较正常请求与实际WAF检测证据；失败回退，连接中断记录UNKNOWN且不自动重复。

新业务：同一入口选择新建业务，生成独立server配置；支持HTTP或目标主机上已有且验证匹配域名的HTTPS证书文件，不上传私钥。只创建尚不存在且被Nginx加载的.conf，不覆盖现有文件；直接创建经WAF的链路。失败/回退删除本次新建文件且保留其他业务。新业务与现有业务共用明确域名、单一location /及HTTP业务上游支持范围。

执行复用AssetRemoteJob，新增kind默认TRAFFIC_CAPTURE，原捕获兼容；NGINX_PREFLIGHT/APPLY/ROLLBACK共用单主机互斥与后台租约。前端展示预检、确认执行、进度与回退，不要求用户下载配置后手动登录。只有目标Agent上报、站点、配置摘要和任务结果一致才算完成。

WAF镜像必须按实际Agent架构选择固定摘要。系统可从平台受管镜像归档下载、核对归档与最终镜像摘要后导入；缺Docker/Nginx或复杂配置时明确报告，不自动安装未知系统组件。平台私钥、数据库配置不得挂入构建/节点容器。

CRS正式运行：固定完整官方原件及入站PL1档位，按既有兼容、原始语料、签名/重放/断网、多节点回执、真实请求和持久化/误报/性能门槛验收。仍使用100RPS、4KiB、95/5、30分钟、4CPU/8GiB、零错误/丢弃、附加P95≤20ms与持续内存标准。不通过时保留失败、修复后再验，不降低门槛。通过后开放本地发布入口，并在自有站点完成观察→准确节点回执→阻断→高版本回退。规则来源检查不自动升级业务站点策略。

新能力需新Agent固定发行版本，不覆盖已发布0.4.12。现场主机接入需另由用户在系统中选择并确认具体变更；本轮不把夹具标为用户业务已受保护。
