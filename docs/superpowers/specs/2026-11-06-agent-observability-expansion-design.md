# Agent 观测能力补充

用户授权按最佳实践选择补充范围，保持旁路，不接管业务流量、不自动部署到受管主机。

本轮交付：
- 将“历史监控窗口”改为“连接与流量记录”，说明每条是时间段汇总而非单次请求；直接列出连接数、包数、字节、平均速率和完整性。保留分页及缺口。
- 监听端口按 socket inode 关联可读取进程，补充程序名称、PID和识别依据；进程扫描有数量/时间预算，不读取命令行、环境或凭据，不提升基础 Agent 权限。常见端口只显示用途提示，不冒充已确认软件；权限不足或非标准端口仍明确显示未知。旧心跳向后兼容。
- MySQL 增加有界预编译语句ID到操作的关联，消费PREPARE响应元数据，EXECUTE保留二进制响应；关闭/连接重置清理状态，缺失上下文、游标和压缩保持缺口。
- Redis 多键命令逐键提取命名空间，避免MSET把值作为对象；HELLO AUTH识别账号和认证结果，配额/前缀限制不标完整分类。索引不保存参数与返回值。
- 对代码回归、主机进程样本及协议样本验收分别记录结果；没有实际版本/内核验收的组合不扩大支持声明。

检测系统路线（本轮设计，不宣称完整IDS已实现）：独立 Suricata 旁路传感器输出 EVE 告警、协议及健康；可选 Zeek 提供协议元数据；Agent 关联端点/进程，上报规则ID/修订/来源与丢包；平台完成定向规则、阈值/基线异常、业务白名单和告警聚合。先验证资源和主机内核兼容，再启用；不自研通用DPI/规则引擎，不自动安装高权限传感器，不自动阻断。

选择此路径是因为已有基础采集与数据探针可直接扩展；单靠端口猜测或自研完整IDS无法提供可信覆盖。HTTP2/多路复用、数据库TLS、Oracle等完整线协议作为独立适配验收项，不能用解析器存在或Agent在线替代真实验收。

## 升级为网络检测系统需要的能力

1. **主机上下文**：将端点、进程、程序/包版本、容器与业务归属关联。进程证据可随权限受限而缺失；当前新增的是可读取的socket/PID关联，不是全权限进程审计。需要更高权限的持续映射应由独立受控助手承担，不能把普通采集器改为root。
2. **独立网络传感器**：指定网卡/命名空间或镜像流量，处理双向TCP会话、重传、重组、分片及协议识别。成熟引擎与基础Agent独立运行，分别限制CPU、内存、队列并可独立停用。
3. **入侵检测**：优先接入Suricata的EVE告警、HTTP/DNS/TLS/流记录与stats/anomaly；保留signature_id、gid、rev、flow_id、规则集版本、来源和更新时间。未部署传感器时显示未接入，不生成“零攻击”的安全结论。依据：[Suricata EVE格式](https://docs.suricata.io/en/suricata-8.0.6/output/eve/eve-json-format.html)。
4. **流量异常**：先做可解释规则：横/纵向端口探测、认证失败聚集、持续外联、流量或返回量异常；再按业务、时段和主机建立基线与白名单。需要去重、采样、抑制和告警证据，不把“新连接”直接认定入侵。当前汇总没有TCP建立/失败语义，不能先用它宣称完整扫描或爆破检测。
5. **TLS与身份**：网络TLS元数据可支持域名/证书/协商分析，正文仍需经组件评审的进程观察点或原生审计。HTTP2/GoTLS/JavaTLS/数据库TLS及旧内核分别验收；共享连接池不能自动映射到最终业务用户。
6. **健康及运营**：丢包、重组缺口、规则加载失败、队列积压、采集停顿和版本更新都必须可见；先在麒麟V10/目标CentOS实机评估CPU/内存/磁盘、吞吐及延迟，再启用。

以上是后续引擎接入方案，当前交付没有安装Suricata/Zeek、没有新建通用IDS告警接口、没有生产异常基线或自动阻断。下一阶段应交付传感器健康+EVE关联+少量可解释告警的完整闭环，再考虑更多协议。
