# 主机统一接入与采集能力管理

## 已确认的目标

用户确认的方向：一台主机只接入一次，在同一流程选择网络采集、数据采集，平台完成组件部署并显示实际采集结果。用户不需要根据内部组件分别找入口、下载配置、再次登记资产。已有业务分组保留。

当前事实：基础 Agent 安装使用固定版本、签名发行、短期票据及心跳验收；网络持续监控另行配置；数据观察源另行授权、下载配置，再在主机安装独立探针。探针本地验收包尚未纳入签名交付通道。Suricata 引擎及桥接器亦为独立部署。目前页面可查历史证据，不能由此宣称已形成常驻业务采集。

## 方案选择

1. 仅合并页面入口：改动小，但仍需用户完成多次安装，不满足本次目标。
2. **统一接入流程，内部按需安装独立组件**：沿用主机身份和各组件权限、队列及服务隔离；增加受管交付、执行及验收。作为本次建议实施方案。
3. 把所有捕获和解析放进基础 Agent：会扩大基础进程权限及故障影响，重写已有实现，不采用。

用户已确认统一接入的产品方向；上述内部实现方式及以下执行边界为本次工程建议，尚待本文评审。

## 用户操作

新主机使用一条流程：

1. 登记主机并选择所属业务；选择网络采集、数据采集所需能力。
2. 核对平台连接地址、安装方式和采集范围，确认安装。已有可信 SSH 管理连接时由平台执行；否则只执行一次统一安装命令。
3. 在同一页面查看接入、组件安装、采集心跳和最新实际访问结果，成功后直接进入网络或数据记录。

第二步中的网络范围、数据端点等为按所选能力展开的表单，不再变成独立安装流程。涉及敏感访问内容的能力必须明确选择，不在主机登记后自动采集全部业务。

已有主机使用“采集配置”增开、停用或调整能力。若基础 Agent 版本不支持，展示所需升级及影响并由用户确认；不悄悄重新登记或覆盖身份。后端使用同一资产和持久身份执行幂等协调，不能仅靠 IP 合并不同身份。

本次不新增高权限远程命令执行守护进程。自动安装和后续组件变更沿用已核验 SSH 管理连接；仅使用命令接入的主机，由同一流程生成一次包含所选组件的签名安装命令。后续增开组件若仍无 SSH 管理权限，则生成一次组件变更命令，明确需要主机管理员执行；不能将此场景标成平台已自动完成，也不重装基础 Agent。这个限制在选择安装方式时说明。

## 能力与边界

### 主机信息

基础 Agent 提供主机、软件、服务及端口信息，是接入基础。沿用已有发行安装和平台验收。主机已登记不等于 Agent 已安装，安装任务成功也不能替代后续心跳。

### 网络采集

勾选后在同一流程配置网卡及已有资源预算，启动持续连接、包数和字节摘要采集；不保留一个默认 30 秒的停止任务。保留临时排障入口作为独立用途。

Suricata 在网络采集下作为可选“入侵检测”，不作为每台主机的必装前置。引擎、桥接器、正式规则来源及加载状态独立验收。已有引擎可接管其只读输出；新装涉及软件包、网卡及规则变更，须在统一安装确认中列明。未完成这些验收前显示待安装或待配置，不显示已防护。

### 数据采集

先列出真实发现的数据库、缓存或接口候选及识别依据，再由用户选择端点。现有主机服务、进程、端口证据复用；端口惯例只能作候选，不将 3306 等端口直接认定为数据库。证据不足时仍允许填写明确端点。不得扫描所有远端 IP 或将每个端点重复创建为主机资产。

对选定端点由平台创建或复用来源、绑定当前资产及数据库实例，生成私有配置，交付兼容且已签名组件，执行现有探针安装器并启用常驻服务。观察源授权、凭据交付、进程启动及收到实际访问分别核验。用户无需下载并搬运凭据文件。

沿用当前 HTTP/1.1、MySQL、PostgreSQL、Redis 的真实适配边界；Oracle、SQL Server、达梦、金仓仍使用已支持的原生审计或标准接入路径，不能显示为已支持完整报文解析。TLS 明文观察保持逐组件评审，自动接入不绕过进程和库版本检查，也不擅自启用数据库审计或修改业务配置。

分类分级和准入/行为规则是后续业务配置，不能由安装器凭空生成。已有分类和规则继续生效；未配置时明确显示未分类、未配置检测或普通访问。用户始终能分别查看普通访问与命中告警。

## 安装与交付约束

- 不新增平行的安装系统。沿用现有发行信任根、固定版本安装任务、SSH 信任校验、权限与作用域检查、主机身份绑定和审计；在其上补齐组件清单及执行状态。
- 沿用现有角色能力：数据观察源与入侵检测管理仍按现有管理员权限控制；操作员只能操作已有授权范围内的能力，不能经统一入口绕过 ADMIN 限制。需要新增授权时显示原因及管理员接续入口，保留已填写内容。
- 数据探针纳入可验证的签名组件交付。包的架构、版本、摘要、有效期及基础 Agent 兼容性在执行前核对；本地未签名验收包不能自动晋级到生产安装。
- 基础 Agent 保持原采集权限；探针抓取、解码上传与独立队列的服务及权限隔离保留，Suricata 引擎也独立运行。统一操作不等于合成一个高权限进程。
- 任务按当前资产身份、配置版本和组件版本幂等执行；重试不得重复创建来源或并发安装同一组件。身份撤销、更换、归档或授权变化均在领取和执行阶段复核。
- 配置、票据和组件凭据只进入受保护的交付通道与本地私有文件，不进入命令参数、普通心跳、列表和诊断日志。证据正文不进入安装日志。
- 失败展示具体阶段及可重试范围。组件失败不回滚已验证的基础接入，不重启业务服务；升级或配置回滚只涉及本次受管组件文件，不删除证据和加密队列。
- 平台地址必须从目标主机可达。当前本地预览的 127.0.0.1 不能直接用于远程主机；地址未解决时应在安装前阻止并解释，不自动创建隧道或把主机迁往另一平台。
- 禁止自动关闭 TLS 校验、主机公钥校验、认证或系统安全机制。主机缺依赖、权限不足、内核不支持或组件未经验证时准确阻止，不悄悄扩大权限。

## 状态和页面

主机接入页按“主机信息、网络采集、数据采集、入侵检测”展示已选能力，各行明确显示：

- 未启用、待安装、安装中、配置待确认、运行中、上报过期、停止或失败。
- 实际运行版本、最近心跳、最近有效记录；健康状态不使用昨天的 RUNNING 作为今天在线证据。
- 没有记录时区分未启动、没有新访问、采集范围不符、不支持、传输失败及容量不足；缺少证据时标记待核查，不猜测原因。
- 提供一个针对当前状态的主操作，例如继续接入、重试组件、查看记录。技术详情按需展开。

沿用顶部菜单、右侧抽屉、现有表单和间距规范；不再新增 Agent/探针的平行资产菜单。数据访问页提示采集是否活跃及最新记录时间，避免把历史验收数据理解为当前业务流量。

## 验收

1. 一台新主机只登记一次，仅执行一次统一安装操作；所选组件真实安装并常驻，无需再次手动搬运配置。
2. 同一主机补开数据采集不重复建资产、不重装基础服务；幂等重试不重复建来源或并发任务。
3. 真实明文 HTTP 与已适配数据库/Redis 访问能进入平台；今日访问显示实际时间、来源与完整性。未启动、不支持、TLS 缺口等都不得显示成功覆盖。
4. 网络持续采集、探针心跳和真实访问分别验证；停止组件后页面及时显示停止或过期，原历史保留。
5. 覆盖凭据撤销、任务执行中的作用域变化、摘要不符、错误架构、旧 Agent、断网重试、配置版本冲突和磁盘/队列限制。
6. 接入入口完成桌面和窄屏真实浏览器验收；沿用现有回归并执行相关前后端、Agent及组件测试。

本设计不恢复已暂停的 121 主机升级或迁移，不直接部署云端。先在当前本地环境和隔离 Linux 实例验收，远程业务主机上线仍遵循已确认的部署范围及组件变更流程。
