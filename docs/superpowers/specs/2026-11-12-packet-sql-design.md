# 从访问报文读取 SQL

用户允许从数据库流量/报文获取实时SQL正文。复用已有访问探针的TCP重组、按端点授权、独立加密证据和七天到期机制，补齐报文SQL解码与同实例展示，不新建一条无关抓包链路。

当前交付以已有PostgreSQL/MySQL线协议为基础：Q/COM_QUERY可显示发送的SQL；Parse/COM_STMT_PREPARE明确显示准备语句，不能冒充执行成功；仅在同一报文内具有可信Parse/Bind/Execute关联时呈现执行请求。跨报文缺准备上下文应明确显示缺口，不插值绑定参数，不从任意字节搜索SQL关键词。

读取经现有证据解密/校验及独立原始证据权限，再同时核对SQL原文权限和实例/主机范围；原文不进入普通索引、审计日志或二次缓存。总请求最多1MiB、SQL正文32KiB/条、最多100条；到期/缺段/乱码/加密/不支持明确说明。不获取登录口令帧。报文只能证明已观测到请求，响应与事务是否提交另按原记录展示。

TLS网卡报文无法直接恢复正文，保持加密校验；已有进程明文探针需要目标内核、运行库、版本及协议实际验收。不能关闭数据库TLS，也不因HTTP TLS探针验收成功声称PostgreSQL TLS已完成。当前生产bpftrace运行时和正常管理员授权仍是激活条件，不通过内部代用管理员创建来源。

数据库实例加入“流量SQL”入口；访问证据详情新增按需读取SQL按钮。全局访问记录保留原筛选行为，同实例入口不能清除实例范围。没有来源时提供明确配置说明，不自动制造演示SQL或修改/重启数据库。
