# 顶部导航与页面详情层级

用户要求：用顶部菜单替代左侧菜单，向下展开更多层级，承载原先弹窗里的内容。采用现有业务中心，不改为网络安全/数据安全两大菜单，不增删现有模块，不改权限、接口和hash路由。当前包含多处有意保留的未提交业务变更，禁止覆盖；不提交或推送代码。

方案：顶部一级业务中心，第二行展示当前中心模块；策略中心第二行保留已有四个分组，第三行展示组内模块。窄屏导航横向滚动，当前项可见，账户操作始终可用。沿用品牌、颜色、字体与AntD。

详情：将长详情、业务配置、安装、流量、数据库、WAF来源/发布等Drawer统一放入主内容区的详情工作区。模块列表保持挂载但在详情激活期间隐藏，保留筛选、分页与已有请求状态。详情内容通过现有RecordFormHost使用的portal模式进入专用容器；组件仍拥有数据、表单与关闭逻辑。工作区只管理已打开详情顺序、面包屑、返回和焦点。嵌套详情逐层返回，处理中保持原有不可关闭约束。账户密码和删除/确认等短操作仍使用Modal；主编辑/创建/导入表单进入详情工作区。独立嵌入且没有工作区时保留原Drawer作为兼容回退。

实现选择：纯横向移动菜单不足以解决详情层级；逐模块重写独立详情路由改动过大且会丢失列表上下文。本次用共享详情工作区复用原内容与状态，不创建并行业务实现，不用CSS隐藏任意兄弟节点的方式模拟页面。现有操作URI保持兼容，浏览器原hash导航不改变；页面返回使用明确的面包屑/返回按钮。

验证：先验证导航覆盖与选中分组；详情工作区需要真实浏览器验证列表隐藏、嵌套返回、焦点与忙碌态、列表状态保留；完整前端测试和类型/生产构建，宽屏与窄屏实际界面核对。上线只替换Web镜像，保留后台与运行中的Agent/流量监测；备份和旧镜像保留，HTTPS与页面摘要校验后验收。

实现审查补充：保留main父详情挂载及其异步资料加载，子操作不取消父请求；切换模块关闭旧表单，跨模块关联修复通过明确的目标路由编辑意图传递。数据库编辑保留父详情并刷新保存后的记录。资产详情拆分六个页内模块，已有AssetInventoryView保留。
