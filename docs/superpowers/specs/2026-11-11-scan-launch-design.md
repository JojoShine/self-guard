# 单次漏洞扫描流程

用户需要从一个明确入口完成一次漏扫，不再自己拼接来源、目标、建单、执行与结果页面。

采用最小改动：在现有漏洞管理首页增加“发起一次漏扫”，选择主机软件或Web/服务检查，显示真实准备项，直接打开已有创建表单。首次操作默认手动执行；保留原计划管理、来源与规则维护入口。表单预览后明确点击“保存并开始扫描”，随后自动打开本次运行并刷新进度，失败保留可恢复的计划，不重复创建。

复用现有表单、预览、创建和执行API，避免平行创建扫描实现。相比重新建设完整向导，此方式保留已验证的权限、固定范围和批准规则；相比仅加帮助文字，消除保存后还要寻找执行按钮的断点。高级字段折叠，默认只展示此次检查必需的目标和检测依据。

不自动批准目标、规则或选择全部主机；不修改后端契约，不扫描未授权业务目标，不重启数据库。缺目标、缺适用来源、缺规则和权限不足显示具体下一步；就绪表示可以继续配置，不表示已扫描。软件版本检查和网络行为检查分别解释。

验收：新入口与准备缺口、直接打开表单、手动默认、预览必需、保存并执行、运行自动更新、执行失败可恢复且不重复建单、只读权限、手机布局；真实执行只用隔离数据库和自有测试对象。
