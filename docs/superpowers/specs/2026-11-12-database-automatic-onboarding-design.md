# 数据库自动接入

用户已同意统一流程：选择实例和主机 → 检查环境 → 安装并启动 → 验证数据；需要重启时明确等待维护窗口，之后继续。复用已登记入口、固定 SSH 主机身份和现有运行监控。不得自动重启数据库，不触碰宿主机业务 PostgreSQL14 的日志配置。

采用现有 SSH 任务和独立、只读数据库采集服务；不扩大基础 Agent 的空采集根目录或修改其身份。运行指标继续使用原只读连接配置。PostgreSQL 首批实现宿主机/明确 Docker 容器的原生 CSV 日志自动接入；其他引擎沿用已支持日志格式的已有文件接入，不虚称可以自动开启未适配厂商审计插件。

SQL 采集服务复用 Go Agent 的原生解析、AES-GCM 队列、7 天原文期限和正式审计入库接口。只读取所选来源，不执行主机任务或发送主机清单。支持日志目录轮转，文件游标落盘之前必须将事件可靠入队；未知、超限、轮转缺失和背压明确呈现缺口。健康上报不包含正文和凭据。

平台后台使用持久化 AssetRemoteJob，重验管理员、实例/资产/入口/SSH身份和实例更新时间，幂等、无不确定操作自动重试。PostgreSQL检查失败不能猜测目标实例。logging_collector 关闭时安装步骤等待维护窗口，不启用 SQL 记录；管理员可显式准备仅 logging_collector=on 的持久配置（不 reload、不 restart），维护后再次检查并继续。已开启 collector 的目标可显式启用受控 CSV SQL 日志，使用独立目录及到期清理。平台自身数据库必须已有经过验证的独立审计入库连接，避免自采循环。

安装成功、采集服务运行、实际 SQL 入库分别展示。SQL 原文仍受独立权限和7天期限控制，不能把连接记录冒充执行记录，不能将没有查询的空状态判为安装失败。
