# 数据访问采集与风险解释闭环

用户已确认先把现有探针做实，沿用现有实现并直接执行；Agent升级和真机平台迁移暂停，不自动安装数据探针。

目标：用户能确认是否真正采集、访问对象的分类覆盖、告警触发条件与最终风险等级。普通访问独立留痕；敏感等级不自动等于异常。原始证据保留七天及独立读取/导出权限不变。

方案：扩展现有观察源、访问记录和数据安全告警。另建规则中心或通用DLP引擎会重复配置，故不采用。源配置新增有版本的对象关联：HTTP按精确路径及方法登记所属实例的对象；PostgreSQL解析RowDescription的relation OID/attribute number，按同一来源、数据库的只读元数据快照关联真实列，快照24小时到期。接口登记关联明确标记为配置依据，不伪称请求实际访问数据库；缺少、过期、部分元数据保持未知/部分覆盖。

采集状态分别显示授权、来源凭据绑定是否有效、基础Agent状态、探针版本/最近心跳、最近有效访问。历史RUNNING不代表当前在线，配置版本不符明确展示。协议适配边界保留。

风险在服务端保存当时快照：命中规则、准入/行为、规则原等级、数据映射最低等级、最终等级、分类定义/体系/来源版本和判定条件。未命中规则不生成告警。现有敏感读取规则可选叠加返回量阈值，明确区别“所有敏感读取”与“敏感且超量读取”。不从HTTP头推断最终用户，不用SQL关键词猜测表名。

不承诺本轮补全Oracle/SQL Server/达梦/金仓线协议、HTTP2、任意TLS、自动业务用户归因或生产性能。本轮验证覆盖真实数据库持久化、实际协议字节与本地UI；不能用登记来源冒充已部署。
