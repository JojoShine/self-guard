# Self Guard 资产发现与数据安全补充需求

**版本：V0.1**  
**日期：2026-11-02**  
**状态：已评审，进入实施**  
**用途：本轮产品范围与验收依据；实施状态及验证证据另见《资产与数据安全实施验收记录》。**

本轮补充资产自主发现与认领、数据分类分级、数据库准入与行为安全，以及主机漏洞和 WAF 规则来源与更新管理。数据库实例已确认作为独立资产管理，并保留与主机、业务和数据对象的关联。

本文为新增需求文档，不替换原《需求建设方案》。本轮增补以评审后的本文为依据；已有实现、未完成代码和历史实施记录均不代表本文需求已验收。

## 1 已确认要求与本次评审范围

### 1.1 已确认要求

| 编号 | 要求 |
| --- | --- |
| R01 | 在手工添加资产之外，根据 Agent 监控到的行为、服务和关联线索自主发现资产，供用户认领。 |
| R02 | 数据安全先建立分类分级体系，为后续数据处理策略和审计风险定级提供依据。 |
| R03 | 数据库实例独立管理，具有独立身份、负责人、业务归属和安全管理入口，同时关联承载主机。 |
| R04 | 数据安全分为准入安全与行为安全，分别覆盖认证鉴权和用户操作数据库的安全。 |
| R05 | 支持数据库安全数据钻取，覆盖 Oracle、MySQL、PostgreSQL、SQL Server、达梦、金仓六类关系型数据库。 |
| R06 | 规则按准入与行为补齐，支持公共规则和各数据库专属规则，适用范围与检测依据完整可查。 |
| R07 | 本轮网络安全聚焦主机漏洞与 WAF，保证规则来源准确，并具有明确的更新周期。 |

### 1.2 待评审的方案细节

下文给出满足上述要求的建议设计。等级名称、发现阈值、数据库支持版本、采集方式、自动处置范围、留存周期和菜单位置尚待评审；这些建议不视为已确认决策。具体待确认项集中在第 10 节。

## 2 业务对象与关联

### 2.1 资产与数据对象

| 对象 | 管理职责 | 主要关联 |
| --- | --- | --- |
| 主机资产 | 系统、进程、服务、软件、Agent 和主机风险 | 可承载多个数据库实例或 Web 服务 |
| 数据库实例资产 | 数据库类型与版本、实例身份、连接入口、负责人、业务归属、采集状态及安全风险 | 关联承载主机、集群、逻辑数据库、账号、审计与规则 |
| Web 服务或站点 | 业务入口、域名、站点与 WAF 防护配置 | 关联主机、业务及 WAF 节点 |
| 数据对象 | 逻辑数据库、模式、表、字段及其分类分级 | 从属于数据库实例，不按主机资产重复建档 |
| 资产候选 | 尚未由用户确认的资产线索及其证据 | 关联发现它的 Agent、主机和已有资产 |

数据库实例的负责人、业务归属、生命周期和风险状态可独立维护，不强制继承主机。一个主机可运行多个实例；一个实例也可关联多个承载节点。集群、节点与实例的关系必须明确，避免把高可用节点误认成互不相关的数据库。

资产身份不能只依赖 IP 或端口。地址变更、代理入口、同机多实例、容器重建和地址复用时，应依照稳定标识及证据进行关联；证据不足时保留候选，交由用户确认。外部或托管数据库允许没有本平台管理的承载主机。

### 2.2 统一关联原则

数据库相关风险、告警、事件及分类分级应关联数据库实例；同时保留采集 Agent 和承载主机等来源信息。原有主机风险继续关联主机。统计需区分主机、数据库实例和数据对象，避免将同一对象重复计数。

数据库实例独立管理不意味着继承主机修复能力。数据库配置修改、账号封禁和连接中断必须具有相应执行能力、授权及审批依据。

## 3 资产自主发现与认领

### 3.1 发现依据

Agent 在现有授权范围内收集以下线索，形成候选与关系：

- 数据库或 Web 服务进程、监听端口、服务状态及允许读取的部署元数据。
- 持续或重复出现的连接关系、访问频率及关联业务活动。
- 已接入的数据库认证与操作审计中明确报告的实例信息。
- 与已有主机、数据库实例、Web 服务和业务分组的关联。

发现结果须标明具体证据、观察时间、来源和判断可信度。端口号只能作为线索，不能单独确定数据库类型；一次连接不能直接证明对端是业务资产，也不能据此确定连接发起方向或资产归属。

发现阈值应可配置，包括观察窗口、出现次数、最近活跃时间和可信度条件。采集权限不足、数据不完整或 Agent 离线时，应展示覆盖情况，不将未发现解释为不存在。

### 3.2 候选列表

候选列表至少展示候选类型与名称、地址及端口、推测数据库类型、来源主机与 Agent、发现依据、首次与最近出现时间、观察次数、可信度、处理状态及可能匹配的已有资产。推测值与已确认值应明确区分。

支持按类型、状态、来源、业务线索、时间和关键词筛选，进入详情查看发现证据与关系。候选不直接计入正式受管资产数量。

### 3.3 认领流程

建议流程为：**发现线索 → 聚合与去重 → 待确认候选 → 用户认领或关联已有资产 → 纳入正式管理**。

用户处理候选时可执行：

1. 新建资产并认领，确认类型、名称、业务、负责人及必要的实例标识。
2. 关联已有资产，补充发现证据和关联关系，避免重复建档。
3. 忽略候选并填写原因，支持后续恢复；重复上报不自动撤销忽略决定。
4. 对明确不需要的地址、进程或服务配置发现排除条件，并保留操作记录。

已认领候选继续收到相同观察时只更新发现信息；并发认领不能创建重复资产。认领只确认管理归属，采集授权、数据库连接凭据和执行权限需分别配置。

### 3.4 资产详情

数据库实例详情应提供基本信息、关联主机及业务、发现与认领记录、采集与适配状态、数据目录与分类分级、准入安全、行为审计、相关风险和变更记录。列表、详情及钻取均遵循当前用户的数据范围权限。

## 4 数据分类分级

### 4.1 分类体系与等级体系

分类表达数据的业务含义，例如个人信息、财务、业务运营、系统管理数据；分级表达敏感程度和潜在影响。两者独立配置，不能仅用一组严重程度标签替代分类分级。

分类体系支持层级、定义、识别依据和维护记录。等级体系支持等级顺序、名称、判定条件及处理要求。可提供初始模板，但具体类别与等级数量由业务评审确定，不默认将通用模板视为组织已批准的标准。

### 4.2 数据目录与定义范围

支持按 **数据库实例 → 逻辑数据库 → 模式 → 表 → 字段** 建立目录并查看分类分级。不同数据库的目录层级须按实际含义映射，不强制将不存在的层级伪装成真实对象。

目录可通过授权的只读元数据采集、审计中出现的对象及人工维护补充。审计中观察到的对象应标明来源，不能据此声称目录完整。字段名称、类型、注释和已批准的识别规则可生成分类建议；读取样本数据需单独授权，默认不采集业务数据值。

分类分级定义至少包含对象范围、类别、等级、判定依据、处理要求、确认人、生效状态、版本和变更时间。支持批量确认与修订，自动识别建议和人工确认结果须区分。

### 4.3 继承与冲突

建议采用以下原则，具体降级权限待评审：

- 下级对象可继承上级定义，并展示继承来源。
- 子级存在更高敏感等级时保留更高等级；降低继承等级需明确权限和理由。
- 一次操作涉及多个对象时，风险评估取相关对象的最高有效等级，并列出全部命中依据。
- 对象不明确、字段范围缺失或定义尚未生效时，显示未分类或部分覆盖，不自动赋予低敏感等级。
- 定义变更保留历史版本，历史事件保留发生或评估时采用的版本；重新评估须单独留痕。

### 4.4 驱动处理与审计

分类分级定义应可被后续策略引用，包括审计留存、展示脱敏、导出限制、审批要求、风险定级和复核要求。处理要求需要可识别的策略项，不能只保留无法被规则使用的文字说明。

平台应区分策略定义、已关联策略与实际执行结果。例如，配置“敏感数据导出需审批”后，需要明确其约束的是平台导出还是数据库侧导出，并显示相应执行能力是否已接入。尚未执行的要求不能显示为已生效防护。

本轮需完成分类分级定义及其与审计风险评估的关联。平台展示和导出的具体处理规则，以及数据库端脱敏、审批拦截和阻断的执行范围，在第 10 节确认。

## 5 数据库准入安全

准入安全覆盖连接建立、认证和授权条件，区分配置风险、实际连接记录和异常告警。

| 方向 | 规则需求示例 | 判定依据 |
| --- | --- | --- |
| 认证安全 | 重复登录失败、异常来源登录、免认证或不安全认证配置 | 认证事件、来源信息、配置或授权元数据 |
| 连接安全 | 明确的未加密连接、未强制加密的配置风险 | 实际连接加密字段与配置检查分别判断 |
| 账号安全 | 高权限账号使用、不必要的共享或默认账号、异常账号状态 | 账号与角色元数据、已定义的账号管理要求 |
| 权限准入 | 超出批准来源、身份、角色或业务范围的访问 | 经确认的授权基线与实际访问记录 |
| 访问条件 | 非批准时段、非预期应用或来源访问 | 用户配置的时段、应用与来源基线 |

密码错误、连接失败或开放端口不能作为明文连接证据；缺少授权基线时，不能直接将一次访问认定为越权。不能读取真实口令来验证弱口令，也不默认开展口令尝试。

准入详情需展示数据库实例、账号、来源、时间、认证方式、结果、加密状态、命中规则、依据和处置结果。未知字段保持未知。

## 6 数据库行为安全与钻取

### 6.1 行为记录

行为安全覆盖已进入数据库后的操作活动。正常操作保留审计记录，达到检测条件时生成风险或告警，两者分别统计和查询。

| 行为方向 | 规则需求示例 |
| --- | --- |
| 查询与读取 | 敏感对象访问、异常频率读取、超出正常业务范围的查询 |
| 批量读取与导出 | 明确导出操作、批量读取、读取规模超过批准阈值 |
| 数据修改 | 对重要数据的插入、更新、删除及异常操作量 |
| 结构变更 | 建表、改表、删表等结构操作 |
| 权限变更 | 授权、撤权、账号与角色权限调整 |
| 审计与安全配置变更 | 关闭审计、修改审计范围或关键安全设置 |

判定必须依赖可验证字段。没有返回行数或读取量时不能判定大批量读取；无法区分查询与导出时不能将普通查询直接标成导出；操作尝试、执行失败与执行成功须区分。

行为记录应尽可能保留原始事件标识、数据库实例、事件时间、账号、来源、应用、会话、操作类型、对象范围、结果、数量指标和采集来源。默认保存必要元数据及脱敏摘要；SQL 正文、参数与返回数据的采集范围需单独确认。

### 6.2 风险定级

风险定级同时引用分类分级、操作类型、规则严重程度、授权基线、执行结果和行为上下文。等级映射及计算方式应可查看、可配置、可追溯，不能把数据等级与告警严重程度简单等同。

事件详情展示命中的分类、等级、定义版本、规则版本和定级理由。未分类的数据继续保留审计与规则判断结果，并显示分级依据缺口，不自动解释为低风险。

### 6.3 钻取路径

支持以下连续钻取，并保留筛选条件和返回位置：

- 业务 → 数据库实例 → 准入记录或行为记录。
- 数据库实例 → 账号或来源 → 会话 → 操作事件。
- 逻辑数据库 → 模式 → 表或字段 → 相关操作与风险。
- 风险或告警 → 原始审计依据 → 命中规则 → 分类分级依据 → 关联事件与处置记录。

支持按数据库类型、实例、账号、来源、操作、对象、时间、分类、等级和结果组合筛选。原生数据不含会话或字段信息时标明缺失，不虚构链路。详情和导出均执行数据范围与证据读取权限检查。

## 7 六类数据库适配与规则体系

### 7.1 完整适配目标

| 数据库 | 需覆盖的适配内容 | 需核实的专属规则方向 |
| --- | --- | --- |
| Oracle | 实例身份、数据目录、账号角色、认证及操作审计 | 用户与角色授权、特权操作、审计配置及对象访问 |
| MySQL | 实例身份、数据目录、账号权限、连接及操作审计 | 账号来源限制、认证与传输配置、权限及数据操作 |
| PostgreSQL | 实例身份、数据目录、角色权限、认证及操作审计 | 连接认证规则、角色授权、传输配置及对象操作 |
| SQL Server | 实例身份、数据目录、登录与数据库用户、认证及操作审计 | 服务器与数据库权限、角色变更、审计与对象操作 |
| 达梦 | 实例身份、数据目录、账号权限、认证及操作审计 | 账号权限、安全配置、审计设置及对象操作 |
| 金仓 | 实例身份、数据目录、账号权限、认证及操作审计 | 账号角色、连接认证、安全配置及对象操作 |

上述为目标范围，专属规则的参数、语义和可用性须依据所支持版本的厂商文档确定。不能因语法相似就将其他数据库的规则直接宣称适用。

每种数据库均需形成适配清单：支持版本与版本形态、采集方式、最低权限、日志或审计前提、字段映射、专属规则、采集限制、部署步骤和验证证据。支持版本在评审后固定。

原生日志解析、只读元数据连接和标准审计格式转换应分别标识。标准格式可作为接入方式，但只有字段映射、来源追溯、失败提示及实际规则验证完整后，才能作为该数据库相应能力的交付；不能仅凭通用格式声明完成全部适配。

### 7.2 规则管理

规则支持按准入或行为、数据库类型、风险方向、启用状态和适用实例筛选。公共规则与厂商专属规则共同维护；数据库专属条件不得下发到不兼容的实例或采集器。

每条规则至少具备：名称、目的、分类、适用数据库及版本、采集前提、判断条件、阈值和窗口、风险等级、分类分级引用方式、依据来源、规则版本、更新时间、例外条件、验证样本、误报说明及处置建议。

支持用户自定义规则、按实例或业务应用规则、离线样本验证、例外期限、版本恢复和变更审计。缺少必要字段或采集能力时显示覆盖不足，不能以“无命中”证明安全。

## 8 主机漏洞与 WAF 规则来源和更新

### 8.1 来源准确性

主机漏洞规则或情报需关联公告来源、公告标识、适用产品与版本、发布时间和原始依据。WAF 规则需关联上游项目或自定义来源、规则包版本、规则标识、许可及原始内容摘要。

界面应区分官方来源、经核验的第三方来源和自定义规则。自定义规则允许使用，但必须如实标识；来源可访问、内容校验通过和规则语义适用是不同检查结果，不能相互替代。

### 8.2 更新周期与状态

每个来源具有可配置的检查或同步周期，展示最近尝试、最近成功、下次计划、当前有效版本、可用新版本、失败原因和过期状态。支持手工更新与定时更新，重复执行不重复导入。

建议初始周期为：主机漏洞情报每 24 小时同步；WAF 上游版本每 24 小时检查，有新版本后生成候选规则包。具体周期与过期阈值待评审；网络或部署环境限制应显示为失败或未执行，不能更新时间戳伪装成功。

更新失败保留最近有效版本，发出可操作提示。漏洞情报同步与 WAF 规则生效分别管理：WAF 候选更新应经过校验、验证和受控发布，并支持回退。本轮优先补齐来源可信性、周期执行和更新状态，不另行扩展网络安全产品范围。

## 9 权限与验收

### 9.1 权限要求

资产发现、认领、分类分级维护、规则配置、审计读取和导出分别受权限控制。按数据库实例限制数据范围，关联主机可见不自动意味着其所有数据库均可见。采集凭据只用于批准用途，遵循最小权限，不在日志或证据中展示。

认领、关联、忽略、恢复、分类分级确认与修改、规则变更、更新发布、审计导出和处置均留存操作者、时间、对象、结果及必要的变更依据。

### 9.2 验收场景

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| A01 | Agent 重复观察同一服务或连接 | 候选聚合，有来源与时间；不重复创建正式资产。 |
| A02 | 只有端口线索或一次连接 | 显示推测与证据不足，不直接认定数据库类型或归属。 |
| A03 | 新建认领、关联已有资产、并发认领 | 结果唯一，关系准确，有权限控制及审计记录。 |
| A04 | 忽略后再次发现 | 保留忽略状态与原因，支持授权恢复。 |
| A05 | 同机多实例、实例多节点或地址变更 | 实例独立管理，主机与节点关系准确，不仅按地址去重。 |
| A06 | 目录发现及分类建议 | 明确来源与覆盖范围，建议和有效定义分开，不默认读取业务值。 |
| A07 | 数据库、表和字段存在不同等级 | 继承与冲突处理符合批准策略，展示最终依据。 |
| A08 | 未分类、部分字段未知或定义变更 | 未知状态如实显示；历史事件保留当时定义版本。 |
| A09 | 分类分级被审计规则引用 | 能解释数据等级、操作与授权等因素如何影响风险结果。 |
| A10 | 登录、连接加密与鉴权检测 | 配置与实际行为分开，字段缺失不推断成功、明文或越权。 |
| A11 | 普通查询、批量读取、导出及修改 | 审计与告警分开，仅在证据和条件满足时报告相应行为风险。 |
| A12 | 实例、账号、会话、对象和事件钻取 | 筛选连续、关联准确；缺少的会话或对象字段不补造。 |
| A13 | 六类数据库逐库验收 | 各自具备版本清单、接入说明、字段映射、准入与行为规则及验证证据。 |
| A14 | 公共与数据库专属规则应用 | 只应用兼容的规则，缺少能力时提示覆盖不足。 |
| A15 | 漏洞和 WAF 来源及周期检查 | 原始依据、有效版本、周期、成功和失败状态可追溯。 |
| A16 | 更新失败或 WAF 新版本发布 | 保留有效版本；候选和生效状态分开，回退可验证。 |
| A17 | 越权读取、修改、钻取及导出 | 服务端拒绝，关联入口不能绕过数据库实例的数据权限。 |
| A18 | 采集中断、重放或日志格式变化 | 有采集异常和丢弃提示；重复事件按来源标识去重，不伪造完整覆盖。 |

正式验收以支持版本内的真实数据库与端到端采集证据为准。离线样本、标准格式校验和单元测试可以证明局部逻辑，不能替代全部厂商原生接入验收。

## 10 待确认事项与建议顺序

### 10.1 待确认事项

| 编号 | 待确认内容 | 建议 |
| --- | --- | --- |
| D01 | 数据分类目录、等级数量、名称与判定标准 | 优先采用组织已有制度；没有现成制度时另行提供初始模板评审。 |
| D02 | 数据对象降级及分类分级审批权限 | 降级需记录理由并由指定角色确认。 |
| D03 | 六类数据库首批支持版本与版本形态 | 按实际部署清单固定版本、审计前提和验收环境，逐库验收。 |
| D04 | 数据库接入方式与采集权限 | 组合使用 Agent、授权只读元数据连接和审计接入，逐项说明所需权限。 |
| D05 | 行为习惯识别与候选提示阈值 | 先采用可解释的时间窗口、频次和证据组合；阈值可配置。 |
| D06 | 分类分级驱动的数据处理执行范围 | 先落实审计定级；明确平台脱敏与导出控制要求，再确定数据库侧执行能力。 |
| D07 | SQL、参数、审计记录与证据留存范围 | 默认必要元数据和脱敏摘要，敏感正文采集需单独授权；周期按等级配置。 |
| D08 | 自动处置范围 | 默认检测与人工处置，数据库封禁、断连和配置修改另行确认执行及审批要求。 |
| D09 | 漏洞与 WAF 更新周期及过期阈值 | 建议每日同步漏洞情报、每日检查 WAF 版本；WAF 发布沿用验证和受控发布流程。 |
| D10 | 菜单与页面组织 | 资产中心新增发现认领和数据库实例入口；数据安全按分类分级、准入、行为组织，并关联统一安全中心。 |

### 10.2 建议推进顺序

1. 确定独立数据库实例模型、资产关系、数据分类分级体系和支持版本清单。
2. 建立资产发现认领流程及数据库数据目录、分类分级维护流程。
3. 完成准入与行为的采集、规则、风险定级和钻取，按六类数据库逐项验收。
4. 补齐主机漏洞与 WAF 的来源核验、周期执行、状态提示及版本追溯；该项可与前述工作并行。

该顺序只规定依赖关系，不削减六类数据库和公共、专属规则的完整目标范围。评审确认后另行形成实施计划，不以本稿直接触发代码开发或部署。
