# 安全观测 P0 验证记录

日期：2026-11-04，续验：2026-11-05。依据：[V0.2 业务规划](网络安全与数据安全业务重构规划评审稿.md)与[实施计划](superpowers/plans/2026-11-04-security-domain-observability.md)。

**状态：P0 进行中。容量工具、首批明文协议与指定 OpenSSL 合成进程的 TLS 分段重组已验证；各数据库 TLS、旧系统组合和生产负载尚未验收。** 本记录中的实验使用诊断工具和隔离环境，不表示 Agent 已具备同等能力，不表示已经部署。

## 1. 有效访问容量工具

已新增[离线测算工具](../scripts/observability-capacity.cjs)，不读取平台配置或连接数据库。显式输入有效访问次数、记录/请求/完整返回大小、保留天数、必要原包量、副本、独立索引保留和缓冲，分别输出各部分字节及总量。拒绝缺项、未知字段、非整数、负数、无效副本/天数及计算溢出；错误不回显输入正文。

本轮先运行测试观察到新模块不存在而失败，再实现；随后补充 FIFO 输入阻塞回归，先观察到超时再修复，最终 9 项测试通过。样例仅用于公式验证：每天 100 万次、每次记录 1 KB 加返回 20 KB，单份正文每天 21 GB、7 天 147 GB；不含返回时为 7 GB，平均返回 1 MB 时为 7.007 TB。以上不是现网测量数据，副本等附加量另算。

### 5.1 TLS 基线与只读观察点

实验为 Python 3.14.9/OpenSSL 3.0.22、aarch64、Linux 7.0.12 的本地 TLS 1.3 合成通信。服务端证书经过客户端信任和主机名校验；完整业务返回 262165 字节。基线原包 267302 字节，不含明文测试标记；密文原包和明文结果分别保存。

默认容器无法创建 BPF map；增加 BPF/PERFMON/SYS_PTRACE 后预检通过，但旧工具仍需要 tracefs。最终使用独立 PID/挂载空间、无网络容器，并额外授予实验所需 SYS_ADMIN，仅在其挂载空间挂载 tracefs；未使用 privileged 或 host PID，未挂载业务目录。该权限组合是本次实验条件，不是已批准的生产 Agent 权限。

探针仅绑定在容器内新复制的私有 `libssl.so.3` 文件 inode 上，该副本只由合成子进程加载。最初 `pid == cpid` 过滤在该容器/旧工具组合中没有输出；改用独有 ELF inode 限定目标后，观察到 `SSL_read_ex`/`SSL_write_ex` 明文。此结果不能证明通用 PID/进程身份选择已实现；正式探针仍需可靠的进程启动身份、命名空间、库版本和会话映射。

重组按线程/调用分组并校验偏移连续、段长度及总长，只选择与客户端预期完全匹配的结果，不能把服务端和客户端观察重复计数。上述为短时、两个合成线程实验；“无报告丢事件”不是生产无丢失保证。并发、异常进程退出、超过单次读取边界的 GAP 分支、不同 TLS 库和旧内核仍未完整验证。

摘要 JSON 中 `readCalls`/`chunks` 是双向合计。离线校验脚本 `assess_tls.py` 已独立复核，文本和二进制 SHA256 均匹配；额外破坏实验中，缺段、重复段和内容篡改均会失败。复核发现的双向/响应计数口径已澄清，无 Critical/Important 问题。实验完成后，两个额外权限测试容器已移除，临时证书随其销毁；工具容器已停止且只保留内部网络。

诊断脚本采用文本/十六进制输出，开销较大，不能直接作为 Agent 的生产全量实现。后续应验证有界二进制事件传递、分段持久队列、丢失计数和会话映射，再按实际组件评审与性能验收。各数据库能力矩阵中的“TLS 明文”仍为未验证，因为本次并未执行数据库 TLS 协议或其实际进程的完整采集。

尚需验证：数据库 TLS 指定组件及库、麒麟/CentOS 真实旧内核、ARM64/x86_64 组合、复杂路径、原包短时缓冲/固化生命周期、配额/解码崩溃/离线恢复、流式内存预算、代表性 CPU/IO/P95、真实有效访问分布，以及后续生产前真实 7 天生命周期。

因此本轮不根据约 1 MB 的合成流量外推现网天容量或固定节省比例。容量工具已可用，现网估算仍需按已授权的代表性数据输入，分类、正文权限及独立证据生命周期继续沿用已确认规划。

## 7. 基础采集/数据探针划分与缓冲实验（2026-11-05）

按用户本轮提出的问题，方案补充为同一受管 Agent 身份下的两类能力：基础主机/流量采集，以及按组件授权的数据探针。分别启停、声明权限和兼容版本，独立工作进程、队列、健康和资源预算，原有主机无需重复认领。该拆分尚未写入现网 Agent，不能把规划当成已运行的进程隔离。

为验证数据链路，在 `.artifacts/results/security-observability/p0-buffer/` 建立了单写者、私有目录的实验原型。仅使用 Node 标准库，未增加生产依赖；不作为 Go Agent 模块或可发布队列。测试先因缺模块失败，实现后通过；独立复核后补充事件确认绑定回归，最终 6 项通过：

| 场景 | 本轮实际验证 |
| --- | --- |
| 加密和重启读取 | AES-256-GCM 保存合成正文，文件不含测试正文；新建队列对象能读取已完成写入，错误确认或不匹配摘要不能删除。 |
| 原包与固化证据分开过期 | 原包到期删除后，提前固化到独立证据目录的内容仍在；过期未固化原包不可回取；证据到自身到期时间后不可读并清理。 |
| 探针满额与基础队列分离 | 探针目录配额满时明确拒绝新数据，旧待确认内容不被淘汰；另一个基础队列仍能保存合成心跳。仅证明目录/预算独立，不等于已验证实际服务崩溃/CPU/磁盘故障隔离。 |
| 重放与真实重复操作 | 同一标识及相同正文/期限幂等；相同标识但不同内容报冲突，不覆盖旧数据；不同标识的相同内容可分别保存。 |
| 确认绑定访问身份 | 内容相同、事件标识不同的两条证据，第一条的确认不能删除第二条；确认同时校验标识、持久化标记和正文摘要。 |
| 篡改及未完成写入 | 修改受认证元数据会报损坏；遗留 `.part` 文件停止正常恢复并显式报错，不静默当成已投递或擅自删除。 |

实验使用注入时钟验证过期边界顺序，不是实际运行 7 天。密钥由测试调用方传入，确认由测试调用方提供事件标识、`persisted` 与摘要；生产密钥托管/轮转、远端确认的鉴权与事务语义、原始产生时间约束尚未实现。原型不支持多写者，不证明目录竞态防护、物理断电恢复、跨进程自愈或真实上传/离线网络恢复，残缺写入目前只报缺口而未自动修复。

独立复核发现旧实验确认只绑定内容摘要，可能误删不同标识但同内容的待确认事件；先以回归测试复现失败，再增加事件标识校验，最终 6 项缓冲测试及 9 项容量测试全部通过。该问题未进入生产代码或已发布 Agent。

后续正式实现须在上述边界上增加进程锁/安全目录访问、可恢复状态机、独立正文队列及经过认证的持久化确认，且保持基础心跳不被探针正文占满；不得直接把该实验原型复制为生产实现。
