# 漏洞情报增量实施计划

继续执行已确认建设方案的阶段五。本阶段保持原有多源完整快照、版本适用判断和定期扫描能力，新增真正的更新读取与快照追溯；不因新增来源格式而自动改变扫描范围或关闭风险。

1. **先实现OSV更新索引**：依据[官方数据说明](https://google.github.io/osv.dev/data/#downloading-recent-changes)，读取明确生态目录的`modified_id.csv`，保留原始修改时间精度、完整原文字节摘要、记录数量及重复/损坏检查。完整读取后才可判断范围，不能读到水位就提前中断、把缺失编号当作移除。
2. **绑定已验证的基线**：只有同一来源、范围与转换器的完整快照可作基线。以原始通告的修改时间比较，不能直接依赖数据库毫秒精度时间。首次同步、缺少基线、变化过多或需要压缩依赖链时使用全量；这属于明确回退方式，不把全量下载称为增量。
3. **逐条验证来源与发布完整快照**：只从固定官方生态和明确编号下载，核对索引与通告身份、版本、所属范围及撤回状态。索引和通告在导出期间发生变化时保留旧快照，不拼凑新旧版本。保留增量原件及其基线、摘要与许可，扫描仍冻结完整有效输入。新增、修改、撤回和离开来源范围分别记录；源缺失不直接证明资产问题解决。
4. **更新可读界面与指南**：展示使用全量还是增量、依据哪个快照、改变了哪些内容、哪里不完整。固定生态和来源模式使用选择器，失败在原页面说明原因与重试路径，不增加嵌套弹窗。
5. **分层验收**：先验证真实官方索引及分片、精度、重复、损坏和超限，再在独立数据库验证基线合并、撤回、幂等、停用/租约失效及原件追溯；最后覆盖真实来源和五种分辨率。NVD、发行版及其他来源分别验证各自更新语义，不共用未经证明的水位规则。

实施期间，WAF参考环境的30分钟负载使用已冻结的独立二进制、凭据和schema；不向其发布新代码或重启其服务。情报模块的部署和完整回归安排在持续负载完成后。
