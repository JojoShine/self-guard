# WAF完整持久链路性能验收计划

沿用已确认建设方案的W11门槛继续实施，不新增用户批准步骤。当前优化版本完整2799阶段逐条结果与基线相同，10秒规则路径预检通过；此前30分钟失败结果仍有效，正式运行发布保持关闭。

1. **隔离真实链路**：使用新的专用API/schema、独立随机组件凭据、临时签名密钥、固定CRS原件及实际WAF进程。节点仅挂载自身二进制与公钥，不挂载项目全目录或API私钥。正常上游与纯代理基线均为明确的自建夹具；不访问业务站点。
2. **启用实际持久化**：事件outbox、访问日志与待投递队列写到明确的磁盘目录，调用真实API落库。先核对观察、阻断、检查失败、准确版本回执、队列重试和数据库记录，再进行负载。不能用内存消费通道代替持久链路，也不能仅看HTTP状态推断落库。
3. **记录运行证据**：固定实际二进制和库摘要、环境资源、4KiB正文、95%正常/5%攻击、100RPS。逐请求记录纯代理与WAF耗时和分类错误；每分钟记录父子进程RSS、工作进程回收、持久队列深度、投递失败和落库进度。测试前后保留配置及资源状态，结束恢复自建夹具原状态。
4. **先短测再持续验收**：短测核对实际持久数据数量与判定，再在4vCPU/8GiB参考环境持续30分钟。要求零判定错误、约100RPS、相对纯代理新增P95不超过20ms、无丢弃记录、队列能够排空且内存稳定；API落库计数须对应实际请求。未达到任何一项时如实保留失败分类，定位代码原因后继续实现，不降低规则范围、移除CPU/内存限制或以短测代替正式验收。

进程故障、全局签名序列及防回放、分区后的灰度和回退仍按扩展验收矩阵独立完成；性能通过本身也不自动代表其余门槛通过。

持续内存证据进一步明确：约每秒采样实际父进程及所有线程创建的工作子进程，30分钟至少1710份有效采样、连续采样间隔不超过3秒、覆盖至少1790秒；合计RSS不超过1GiB。略过最初一分钟，比较随后五分钟与末尾五分钟RSS的P95，末尾增量不超过32MiB或前窗P95的20%（取较大者），为GC和有界工作进程回收保留波动空间。该标准用于判断本次持续负载，不能证明任意未来负载无泄漏。

负载结束后保持真实节点和API在线，直接读取节点磁盘中的访问待投递目录与事件outbox，最多30秒等待两者排空；API另核对180020条ACCESS、9001条WAF_ATTACK遥测和9001条安全事件。独立验收程序重算全部180000条请求的实际状态与新增P95，不信任报告中自填的汇总结果；只有完整参考资源、原始请求、入库、排空、无丢弃及持续内存证据全部满足，才设置performanceAcceptance。fullAcceptance仍为false，以保留其他WAF门槛独立验收。


内存与队列目前按每秒采样，逐项保存实际Go单调经过时间和UTC审计时间。采样间隔、持续覆盖和前后五分钟窗口按单调时钟核对，避免虚拟机UTC校准导致跨度失真；不得根据采样索引补造经过时间。旧报告没有该字段时保留为未验证。内存、错误、计数及20ms门槛均不放宽。正式持续验收期间不并行执行构建、数据库大库导入或其他压测，以减少对参考资源的干扰；干扰期间的失败结果仍保留。
