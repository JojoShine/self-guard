# 主动扫描实施计划

依据已确认的《Agent-WAF-漏洞扫描建设方案》阶段六继续实现。此文件记录执行顺序和验证门槛，不新增用户批准步骤，不启用未经验证的生产扫描。

1. 明确目标、地址及路径边界：冻结主机、协议、端口与解析地址；每次连接重新核对DNS并直连已批准IP。显式内网目标允许；元数据、保留地址及平台控制面不允许。验证DNS变化、混合响应、IPv4映射、编码路径和重定向越界。
2. 自研只读TCP、TLS、HTTP检查：固定GET/HEAD、有界匹配、超时与响应预算；记录真实连接和响应摘要。验证本地协议夹具、超限/中断/取消均不能变成检查通过。
3. 数据库任务及额度：最多4任务、全局50HTTP请求/秒、每目标2请求/秒、每轮300请求，跨工作进程共享预算。验证并发领取、恢复、取消、维护窗口与授权撤回。
4. 规则与计划交互：类型、目标、来源、范围和模板明确选择，输入有业务说明，范围预览和模板转换报告在原页面呈现。先支持有测试样本的自研有限模板，再补外部HTTP模板转换；不调用外部扫描引擎。
5. 可读风险与覆盖报告：实际请求、响应特征、匹配条件和目标链路来自运行证据；不完整或不支持项保持无法判定。跨来源去重、对应复测与五分辨率布局通过后再开放运行入口。

当前：网络目标和自研有限HTTP模板管理、固定批准版本的主动计划、实际Go监督进程、共享额度、逐项提交、原子风险写入、完整HTTP/TLS依据和五分辨率界面均完成本地链路验收；191项API（181通过/10跳过）、77项前端及最终构建通过。主库已部署29条迁移，业务数据保持，网络目标/模板/主动计划/检查均0，未启动未知业务扫描。独立TCP/TLS协议、外部HTTP模板转换、真实进程故障及跨节点压力矩阵继续实施；WAF正式发布门禁仍需按单独验收要求处理。

后续任务持久化约定：网络计划只选择已批准的入口与模板，并冻结ID、版本和批准摘要；扩展至各50项，最多2500个明确组合（每资产每轮仍限300次实际请求）。每次运行按归属资产建立目标，逐个检查单独存证并分页读取，避免把大量响应证据堆进同一JSON。每次请求、结果接收和同事务风险写入均重新核对批准、当前负责人、窗口与资产；来源变更后旧计划不会自动扩大范围。取消、进程恢复及请求额度跨重启保留，未完成不自动关闭风险。样本只用于规则校验，真实风险必须来自实际响应。

外部HTTP模板转换将依据ProjectDiscovery官方字段及匹配关系逐项保持语义，保留冻结来源、MIT许可及转换报告，不调用外部执行引擎。参考：[HTTP协议](https://docs.projectdiscovery.io/templates/protocols/http/basic-http)、[匹配器语义](https://docs.projectdiscovery.io/templates/reference/matchers)、[模板许可](https://raw.githubusercontent.com/projectdiscovery/nuclei-templates/main/LICENSE.md)。外部模板默认不跟随重定向，与当前自研引擎默认行为不同；转换时必须显式保留该差异，不能静默沿用。

外部原件管理已接入固定三份官方HTTP模板及用户上传，保留原件、许可证、转换报告及派生来源，逐路径独立批准；域名变量按每个目标冻结，缺失不发猜测请求。真实官方原件闭环与后续兼容项继续逐项验收，不能把三份模板通过视为全库兼容。
