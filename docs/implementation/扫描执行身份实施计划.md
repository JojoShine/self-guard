# 扫描执行身份实施计划

依据已确认建设方案第9节与V09，按已授权自主实施补齐组织计划的明确执行身份，不扩大已有目标或任何负责人权限。

## 设计与边界

采用独立的扫描专用身份记录，仅用于计划授权，没有登录口令、API凭据或通用用户权限。管理员维护名称、启停与范围；范围只能明确选择已有资产、稳定业务分组，或明确选择全部授权资产，空选择被拒绝。普通分析人员不能创建或变更组织授权。与创建隐藏用户、把授权塞进任意配置JSON相比，专用记录及关联可追踪、不可误用于登录，关系由数据库约束。

计划默认仍使用负责人身份，旧计划不自动关联新身份。管理员可以为库存或网络计划明确选择专用身份；绑定其授权版本。每次运行固定身份ID、版本、范围及授予依据。身份范围、启停或版本变化立即阻止下一次执行许可与旧结果提交；重新启用身份不自动恢复旧计划，需管理员重新预览并保存绑定。

实际范围为计划范围、负责人当前允许范围、服务身份范围的交集。负责人停用或失去扫描/证据权限仍会暂停计划。既有负责人完整数据范围要求保持，不借此开放原来未支持的受限账号管理接口。目标在创建、预览、入队、领取、每次请求/连接许可与结果提交分别检查。范围内多维选择的并集只发生在同一身份的资产/业务授权内，不能把计划与身份授权取并集。

身份名称修改不改变授权版本；范围或启停改变才增加版本。身份不能删除以免历史失去引用。管理员更新身份时不与逐项执行反向持有运行锁；授权版本使旧许可立即失效，工作进程按既有机制记录授权变化并暂停。界面显示绑定是否有效，禁用失效授权的立即执行入口。更新身份不能自动替换计划的旧绑定版本。

## 实施及验收顺序

1. 增加专用身份、计划关联/版本、运行冻结身份字段，默认空值保持旧行为；独立测试模式迁移验证，不在长测期间改动运行数据库或生成客户端。
2. 先用失败测试覆盖空范围、未知/归档资产、无权授予、身份跨计划引用、版本变化、停用与重新启用，以及旧计划兼容。
3. 库存与主动计划的预览、入队和执行共享身份检查；真实TCP/HTTP夹具验证范围外零连接、在途撤销旧结果不提交及定时计划失权暂停。
4. 使用AntD列表及页内表单管理身份，15条分页；资产/业务/身份均选择，字段提供业务提示，详情显示本次冻结授权；不增加二次弹窗。
5. 完整隔离API回归、前端测试/构建及五分辨率实际流程通过后，独立备份并部署，前后业务数量与历史事实摘要一致；更新操作指南与验收矩阵。
