## 执行及验收顺序

1. 确认待定输入，记录实际支持的前后端/数据库组合及入口路径。
2. 补齐运行镜像、数据库角色、显式迁移/初始化、健康检查及完整生产配置。
3. 在隔离数据库验证首次部署、重复迁移、重复初始化不覆盖密码/数据、运行权限、持久化重启和端到端入口；不在当前业务数据库制造测试记录。
4. 通过 GitHub Actions 构建并验收候选产物，记录后端、可选前端、数据库和必要其他组件的准确摘要；发布配置与产物同版本。
5. 只读检查目标服务器的系统、架构、端口、磁盘、Docker/Compose 和 Nginx 现状；确定业务目录及入口，不覆盖其他项目。
6. 备份目标已有相关配置/数据，拉取产物，准备数据库角色，执行迁移、必要首次初始化，再启动应用；前一步失败即停止部署后续步骤。
7. nginx -t 通过后才平滑加载独立业务片段，验证实际入口和 Agent 平台身份。
8. 验证 Agent 下载/安装/心跳和采集；保留当前及上一版本配置、发布清单、产物和可恢复备份。
