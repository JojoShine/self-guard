# 多源情报与软件漏洞检测实施步骤

继承已确认建设方案及追加交互要求，持续实施，不需要再次确认。

1. 归一化 OSV、Alpine SecDB、NVD CVE、CISA KEV，保留原始摘要、来源版本、别名、评分和适用条件。KEV仅补充利用优先级，CPE仅作为适用线索；缺少评分保持未评级。
2. 增加可选来源范围、不可变快照和有租约的同步任务。分页/分批入库，只有完整来源范围可替换当前版本；失败保留旧版本，重复内容不复制情报。
3. 将来源类型、发行分支、仓库与同步范围做成选择；输入提供业务说明。快照、记录和覆盖在同一页面查看，不叠加第二弹窗。
4. 自研版本算法和清单匹配按生态验收；发行版来源优先考虑回移补丁。NVD、KEV只通过漏洞标识补充已确认的组件证据，不凭通用描述制造命中。
5. 补齐 OSV 按生态全量/增量、NVD分片分页、Debian/Ubuntu/RPM官方来源、依赖/SBOM与定期任务；各来源完整性、过期和冲突独立显示。
6. 实测真实官方数据、失败与恢复、重复同步、同一CVEs多来源、权限与范围、扫描覆盖和前端五种分辨率。专用能力未实现时继续开发，不能以兼容说明代替交付。

现有OSV单条转换保持历史兼容，新情报快照不以大量生成Rule记录代替数据库和版本管理。
